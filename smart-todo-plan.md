# Smart Todo App — Architecture & Implementation Plan

> **Framework**: CORE (Capture · Organize · Review · Engage)
> **Tech Stack**: React Native (Expo)
> **Philosophy**: Frictionless, minimalistic, semantically intelligent

---

## 1. Product Overview

A smart productivity app built on the CORE framework that treats everything as either a **Task** or a **Note**. The app minimizes screens and maximizes context-awareness — the main screen adapts to show what matters *right now*.

### CORE Mapping

| Phase       | What Happens                                                        |
|-------------|---------------------------------------------------------------------|
| **Capture** | User dumps tasks, ideas, notes, media into a frictionless inbox     |
| **Organize**| Items get importance scores, semantic links, sub-tasks, and due dates|
| **Review**  | Smart dashboard surfaces what's relevant based on context & time    |
| **Engage**  | User executes tasks, references linked notes, checks off sub-tasks  |

## 2. Data Model

Everything in the app is a **Task** or a **Note**. Both share a common `Item` base.

### 2.1 Base Item (shared fields)

```
Item
├── id              : UUID
├── type            : "task" | "note"
├── title           : string
├── content         : string (markdown / plain text)
├── media           : MediaAttachment[] (images, audio, files)
├── embedding       : float[] (semantic vector, 384-dim)
├── tags            : string[]
├── createdAt       : datetime
├── updatedAt       : datetime
├── archivedAt      : datetime | null
└── links           : SemanticLink[] (to other items)
```

### 2.2 Task (extends Item)

```
Task : Item
├── userPriority    : "low" | "medium" | "high" | "critical" (user-facing label)
├── importance      : float (0.0–1.0, adaptive, computed — see §2.5)
├── dueDate         : datetime | null
├── isAllDay        : boolean (if true, time component is ignored)
├── recurrence      : RecurrenceRule | null
│   ├── frequency   : "daily" | "weekly" | "monthly" | "custom"
│   ├── interval    : int
│   ├── daysOfWeek  : Day[] | null
│   └── endDate     : datetime | null
├── parentId        : UUID | null (for sub-tasks, self-referential)
├── subtasks        : Task[] (children)
├── completedAt     : datetime | null
├── completedSubtasks: int (denormalized count)
└── status          : "pending" | "in_progress" | "done" | "waiting"
```

### 2.3 Note (extends Item)

```
Note : Item
├── pinned          : boolean
├── color           : string (hex, for visual organization à la Google Keep)
├── checklist       : ChecklistItem[] | null (optional inline checklist)
│   ├── text        : string
│   └── checked     : boolean
└── source          : "manual" | "voice" | "media_capture" | "share_intent"
```

### 2.4 Semantic Link

```
SemanticLink
├── fromId          : UUID
├── toId            : UUID
├── similarity      : float (0.0–1.0)
├── autoGenerated   : boolean
└── createdAt       : datetime
```

### 2.5 Importance Scoring — Dual-Layer System

The user never sees a raw number. They assign a **label** at creation time. Behind the scenes, a **numerical adaptive score** is computed and continuously updated.

**User-facing labels** (chosen at capture via a segmented control):

| Label      | Base Weight | Description                       |
|------------|-------------|-----------------------------------|
| `low`      | 0.25        | Nice to have, no urgency          |
| `medium`   | 0.50        | Should get done, moderate priority |
| `high`     | 0.75        | Important, needs attention soon   |
| `critical` | 1.00        | Must do, top of mind              |

**Adaptive importance score** (computed, 0.0–1.0):

```
adaptiveScore = clamp(0, 1,
  userBaseWeight                    × 0.35   // label seed
  + dueUrgency(now, dueDate)        × 0.25   // 1.0 when overdue, 0.0 when >7 days away
  + dependencyRatio                 × 0.15   // subtasks completed / total subtasks
  + semanticContextRelevance        × 0.10   // similarity to recently active items
  + recency(now, lastTouchedAt)     × 0.10   // 1.0 just touched, decays over time
  + siblingPressure                 × 0.05   // how many other tasks compete at same level
)
```

The score is **recalculated** every time:
- The dashboard renders
- A task is completed or created
- The due date passes (urgency jumps)
- A linked item changes

The label is the only thing the user sets — everything else adapts automatically. The dashboard sorts by `adaptiveScore` descending, so the most *objectively urgent and relevant* tasks always surface first regardless of when they were created.

**Important**: the adaptive score is never shown to the user. They see the label badge (`Low` / `Medium` / `High` / `Critical`) and the dashboard order. The number is purely internal.

### 3.1 Smart Dashboard

The main screen is **adaptive** — it shows different cards based on context:

| Card | Logic |
|------|-------|
| **Today's Schedule** | Tasks due today + calendar events, sorted by time |
| **High-Importance** | Top 3-5 tasks by importance score that are not done |
| **Relevant Notes** | Notes semantically similar to recently active tasks |
| **Recurring Due** | Recurring tasks that need attention today |
| **Suggestions** | "You have a note about X, and task Y is related — want to link them?" |
| **Quick Wins** | Low-effort tasks (no sub-tasks, short titles) that are overdue |

Cards appear/disappear based on data availability — empty states are hidden, not shown with placeholders.

### 3.2 Quick Capture

The FAB (floating action button) sits at the **bottom-right** of the dashboard. Tapping it does **not** open a sheet immediately — instead, it expands two labeled options:

| Option | What opens |
|--------|-----------|
| **Task** | Task capture sheet (title, description, calendar date picker, time picker, importance selector, recurrence) |
| **Note** | Note capture sheet (title, content area, media attachments, checklist toggle) |

The user **always** chooses the type explicitly. There is no auto-classification — the intent is clear at the moment of capture.

**Task capture sheet fields:**
- Title (required)
- Description (optional, markdown)
- Due date — opens a **calendar picker**; if the task is not all-day, a **time picker** is also shown
- Importance — **multiple-choice selector** (see §2.5): `Low` · `Medium` · `High` · `Critical`
- Recurrence (optional, defaults to None)
- Sub-tasks can be added after creation from the detail view

**Note capture sheet fields:**
- Title (required)
- Content (rich text / markdown, or checklist mode)
- Media: camera, gallery, voice memo
- Pin toggle, color picker

### 3.3 Search Overlay

- **Semantic search**: type natural language ("that thing about the project deadline")
- **Filter chips**: Tasks, Notes, Today, This Week, High Importance, Recurring
- **Recent items**: last 10 accessed items for quick re-access
- **Results**: grouped by relevance, showing linked items inline

### 3.4 Detail Sheet

A bottom sheet that expands to show:

**For Tasks:**
- Title (editable inline)
- Importance label — segmented control: `Low` · `Medium` · `High` · `Critical` (user can change after creation)
- Due date — **calendar picker** (month view, tap to select); if not all-day, a **time picker** (hour:minute wheel) appears below
- All-day toggle (on by default — hides time picker)
- Recurrence settings
- Sub-tasks list (add/reorder/complete)
- Linked notes (auto-suggested + manual)
- Content/description (markdown)
- Media attachments

**For Notes:**
- Title (editable inline)
- Content area (rich text / markdown)
- Media gallery
- Pinned toggle, color picker
- Linked tasks and notes
- Checklist mode (toggle)

### 4.3 Semantic Search Strategy

**Approach: On-device embeddings with `@xenova/transformers`**

```
Capture → Text preprocessing → Embedding model (all-MiniLM-L6-v2) → 384-dim vector
                                                                        ↓
                                                              Stored in SQLite (BLOB)
                                                                        ↓
Query → Embed query → Cosine similarity against all stored vectors → Ranked results
```

- Model: `Xenova/all-MiniLM-L6-v2` (~23MB, fast on mobile)
- Embeddings stored as BLOB in SQLite
- Cosine similarity computed in JS (fast enough for <10k items)
- Re-embedding triggered on content edit (debounced)

**Alternative (if on-device is too slow):**
- Offload to a lightweight backend (e.g., Supabase with pgvector)
- Or use Expo's `expo-task-manager` for background embedding

## 5. Core Feature Implementation Details

### 5.1 Quick Capture Flow

```
User taps FAB (bottom-right)
    ↓
Two options expand: [Task]  [Note]
    ↓
User taps "Task"
    ↓
Task capture sheet opens:
  1. Title field (auto-focused, keyboard open)
  2. Description field (optional)
  3. Due Date row → tap opens calendar picker
     └─ "All Day" toggle ON  → time picker hidden
     └─ "All Day" toggle OFF → time picker (hour:minute) appears
  4. Importance row → segmented buttons: [Low] [Medium] [High] [Critical]
  5. Recurrence row → dropdown: None / Daily / Weekly / Monthly / Custom
    ↓
User fills fields and taps "Save"
    ↓
Item created with:
  - userPriority from selected label
  - Adaptive importance computed immediately (see §2.5)
  - Auto-generated embedding from title + description
  - Auto-linked to semantically similar existing items
    ↓
Brief confirmation (haptic + subtle toast)
    ↓
Sheet closes, dashboard re-sorts by adaptive score
```

**Note capture** follows the same pattern but without date/importance/recurrence — just title, content, media, and optional checklist mode.

### 5.2 Sub-Task System

- Tasks can have unlimited sub-tasks (tree structure)
- Sub-tasks are full `Task` items with `parent_id` set
- Sub-tasks inherit the parent's due date by default (can override)
- Importance of parent is boosted when sub-tasks are near completion
- Sub-tasks can be added at any time, even after task creation
- Completing all sub-tasks suggests completing the parent

### 5.3 Recurrence Engine

```
RecurrenceRule
├── frequency: "daily" | "weekly" | "monthly" | "yearly" | "custom"
├── interval: 1 (every day), 2 (every other day), etc.
├── daysOfWeek: [1, 3, 5] (Mon, Wed, Fri)
├── dayOfMonth: 15 (15th of each month)
├── endDate: null (forever) or specific date
└── exceptions: [dates to skip]
```

When a recurring task is completed:
1. Current instance marked `done`
2. New instance created with next due date
3. Previous completion history preserved

### 5.4 Semantic Linking Engine

Runs automatically on:
- **Item creation**: scan for similar items, create links above threshold (0.7)
- **Item edit**: re-embed, update links
- **Periodic scan**: background job to find new connections

```
For each new/updated item:
  1. Generate embedding
  2. Compute similarity against all other items
  3. If similarity > 0.7 → create auto-generated link
  4. If similarity > 0.5 and < 0.7 → suggest link (shown in UI as "Related?")
  5. Store top N links per item
```

### 5.5 Smart Dashboard Logic

The dashboard recalculates its cards on:
- App foreground
- Item create/update/complete
- Time change (new day)
- Context change (location, calendar)

```typescript
// Pseudocode for dashboard card generation
function generateDashboardCards(items: Item[], now: Date): Card[] {
  const cards: Card[] = [];

  // 1. Today's Schedule
  const todayTasks = items.filter(isTask)
    .filter(t => isDueToday(t) && !t.completedAt)
    .sort(byTime);
  if (todayTasks.length > 0) {
    cards.push({ type: 'today', items: todayTasks });
  }

  // 2. Highest Adaptive Importance
  const topTasks = items.filter(isTask)
    .filter(t => !t.completedAt)
    .sort(byAdaptiveScore)   // computed score, not the label
    .slice(0, 5);
  if (topTasks.length > 0) {
    cards.push({ type: 'importance', items: topTasks });
  }

  // 3. Relevant Notes (based on recently active tasks)
  const recentTaskEmbeddings = getRecentTaskEmbeddings(items);
  const relevantNotes = findSimilarNotes(recentTaskEmbeddings, items)
    .slice(0, 3);
  if (relevantNotes.length > 0) {
    cards.push({ type: 'relevant_notes', items: relevantNotes });
  }

  // 4. Recurring Due Today
  const recurring = items.filter(isTask)
    .filter(t => t.recurrence && isDueToday(t));
  if (recurring.length > 0) {
    cards.push({ type: 'recurring', items: recurring });
  }

  // 5. Quick Wins
  const quickWins = items.filter(isTask)
    .filter(t => isOverdue(t) && !hasSubtasks(t))
    .sort(byEffort)
    .slice(0, 3);
  if (quickWins.length > 0) {
    cards.push({ type: 'quick_wins', items: quickWins });
  }

  return cards;
}
```

## 9. Risks & Mitigations

| Risk | Impact | Mitigation |
|------|--------|------------|
| On-device embedding model too slow | High | Fallback to keyword search + TF-IDF; lazy model loading |
| SQLite performance with many items | Medium | Indexing, pagination, archive old items |
| Battery drain from background jobs | Medium | Batch operations, respect system power settings |
| App size with ML model | Low | ~23MB model is acceptable; consider lazy download |
